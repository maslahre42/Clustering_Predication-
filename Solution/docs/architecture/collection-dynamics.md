# Historical collection dynamics

`CollectionDynamics.cs` adds material-level descriptive analysis to `CollectionPatterns.Dynamics` in the existing analytics response. It uses only observations through the inclusive history cutoff, keeps location/material identity, collapses duplicate same-day visits consistently with existing pattern analysis, and resets after every visit, including unknown readings.

The response distinguishes recorded collections, intervals between visits, ordinary numeric cycles below 100%, full/overfull lower-bound cycles, unknown cycles and zero-fill cycles. The first observation counts as a collection but has no preceding interval. Numeric cycles plus lower-bound cycles plus unknown cycles reconcile to all intervals. Zero-fill cycles are part of the ordinary numeric count and retain zero rates.

Cadence uses every known inter-visit interval. Exact cycle rates use numeric fill below 100 divided by the days since the preceding visit. Full/overfull readings supply no invented 110% value and are excluded from exact rate statistics. Each positive ordinary cycle projects an empty-to-full time as `100 × interval days / numeric fill`; this is a constant-speed extrapolation, not an observed overflow time or a calibrated forecast. Zero fill has no finite projected full time. Full/overfull and unknown cycles are counted separately rather than assigned exact times.

Each distribution has count, minimum, maximum, median, quartiles and eight histogram buckets. Seven buckets cover zero through the 95th percentile (or a minimum upper scale of one unit); the final labelled bucket retains every value strictly above that limit, so extreme observations do not flatten the typical distribution. Quartiles interpolate at `(n − 1) × q`. Bucket maxima include the final endpoint; empty cohorts return null, and all-zero rates produce finite buckets. The cumulative projection chart uses daily points from zero through 90 days. Cycles projecting beyond 90 days remain in its denominator. A 28-day guide is explicitly a comparison, not evidence of a fixed collection schedule. Statistics pool cycles; frequently visited bins receive more weight.

Fastest/slowest rankings keep only bins with three or more positive ordinary cycles, sort by median projected full time and location ID, and return up to ten per material and direction. Both recorded collection counts and interval counts remain visible. The ranking is historical evidence, not a dispatch instruction.

The frontend owns material/ranking controls and display geometry in `features/analytics/state/createCollectionDynamics.ts`; `CollectionDynamicsPanel.vue` renders the response, plots histograms and the cumulative curve, and emits the existing location-inspection action. No new API query parameters or database writes were added.
